Tiqlo 像素组件设计说明

统一 Tiqlo Clock 的视觉、交互、响应式布局与无障碍行为，为页面提供稳定、可复用、与业务解耦的 Pixel UI 契约。

Flutter Minimal Pixel UI lib/core/ui/pixel Dark Theme
01

设计目标

时间内容优先

像素装饰不能削弱时钟和关键操作的远距离可读性。

语义先于色值

通过 Token 表达背景、表面、强调、危险与禁用，不依赖散落色值。

硬边像素几何

轮廓由水平线、垂直线和整数阶梯组成，不使用连续圆角。

状态完整

默认、悬停、焦点、按压、选中和禁用状态均可识别。

输入方式无关

触摸、鼠标、键盘和辅助技术拥有等价的操作能力。

业务解耦

公共组件不读取 Provider、路由或业务模型，只接收数据与回调。

2.1 语义颜色

2.3 间距、尺寸与几何

  • 基础间距：4 / 8 / 16 / 24dp。
  • 交互区域：至少 48 × 48dp。
  • 标准 Switch 图形：64 × 40dp。
  • 色彩 Board：默认最小宽度 144dp。
  • 二级页面页头：固定高度 71dp。
  • 所有像素轮廓关闭抗锯齿，并尽量对齐物理像素。

03

组件架构

依赖只允许自下而上：设计原语不依赖具体组件，公共组件不依赖 feature，页面组合层不读取业务状态。

页面组合层PageScaffold · PageList · Header · Section · Toolbar · Sheet
业务可用组件层Button · TextButton · ActionTile · SelectionTile · ColorOption · Switch
交互与外观基础层PixelPressable · PixelPanel · ThemeOptionFrame · ThemeSheetFrame
设计原语层PixelTheme · PixelTokens · pixel_shape.dart · CustomPainter
import 'package:flutter_tiqlo_clock/core/ui/ui.dart';

PixelPressable、Frame、Shape 和 Painter 属于内部基础能力，只有开发新的公共 Pixel 组件时才直接导入对应文件。

04

组件职责

PixelPageScaffold

统一二级页面背景、Safe Area、阅读宽度、页头和正文约束。

PixelPanel

统一切角、轮廓、填充、硬阴影、裁切和 DPR 对齐。

PixelSection

生成设置分组标题、阶梯外框和可选分隔线。

PixelSheet

统一遮罩、滚动、焦点闭环、Esc 关闭、拖拽和焦点恢复。

PixelButton

主要、次要和危险操作；使用 Tone 表达操作层级。

PixelTextButton

用于 Welcome 导航等低视觉权重的文字操作。

PixelActionTile

整行跳转或菜单入口，支持 leading 与 trailing。

PixelToolbar

一组同级操作，按可用宽度自动纵向排列或换行。

PixelSelectionTile

单选项目，通过描边和像素勾选冗余表达选中态。

PixelColorOption

色彩选项，通过色环、勾选和 Board 描边表达状态。

PixelSwitch

布尔设置，通过轨道、滑块位置和 checked 语义表达值。

PixelInfoRow / LinkTile

只读元数据与带说明的整行链接。

选中、开关和危险状态不能只依赖颜色，必须同时提供形状、位置、图标或语义提示。

05

交互状态模型

PixelPressable 维护 enabled、hovered、focused 和 pressed。选择值由业务层受控传入，组件只通过回调请求变更。

DISABLED> PRESSED> HOVERED> DEFAULT
  • 回调为 null 时不可触发，并暴露禁用语义。
  • Enter、Space 与 Pointer 点击触发同一个回调。
  • 焦点态可与选中、悬停、按压态共存，不能被覆盖。
  • 语义树只暴露一个操作节点，内部装饰使用 ExcludeSemantics。
  • 按下时内容向下偏移并缩短硬阴影，不使用缩放或弹跳。
06

动效设计

动效Token / 时长约束
按压与焦点反馈100ms硬边位移和透明叠层
Switch 切换150ms使用阶梯曲线
Flip 翻页700ms上下半卡 3D 翻转
Splash 淡入300ms不额外缩放
Welcome 翻页300ms内容状态同步更新

组件通过 tokens.motionDuration(context, duration) 响应 MediaQuery.disableAnimations。减少动态效果开启时，动画归零但状态立即更新。

07

响应式设计

  • 竖屏页面宽度为 min(可用宽度, portraitMaxWidth) 并居中。
  • 横屏使用完整 Safe Area 宽度，通过 AdaptivePageLayout 决定分栏。
  • PixelToolbar 在小于 600dp 的竖屏中使用全宽纵向按钮。
  • PixelSheet 在紧凑屏使用可用宽度，宽屏限制为 720dp。
  • Theme Sheet 紧凑竖屏最大高度 78%，一般场景 80%，横屏 90%。
  • 文本行允许高度增长，页面保持可滚动，避免文字放大后内容不可达。

响应式判断应基于当前约束或 AdaptivePageLayout，不得根据设备型号维护两套页面。

08

无障碍设计

  • 按钮使用 button 语义，选择项使用 selected，开关使用 checked。
  • 图标操作提供可朗读的 semanticLabel。
  • 分页器朗读“第 N 页，共 M 页”，分组标题标记为 header。
  • Sheet 打开后焦点限制在面板内，关闭后恢复至触发控件。
  • 所有操作区域至少为 48 × 48dp，并支持 Enter 与 Space。
  • 主文字和背景达到 WCAG AA；焦点色与选中描边明显不同。
  • 在 2x 文字缩放下验证内容完整、可滚动且操作仍可触达。

10

扩展组件流程

  1. 明确跨页面语义，确认现有组件不能通过组合满足。
  2. 定义受控 API，将展示数据、当前状态和回调分离。
  3. 颜色、字号、间距和动效复用 PixelTokens，轮廓复用既有 Shape。
  4. 补齐默认、悬停、焦点、按压、选中/checked 和禁用状态。
  5. 确保触摸、鼠标、Enter、Space 和辅助技术行为一致。
  6. 验证窄屏、横屏、Safe Area、长文本和 2x 文字缩放。
  7. 公共组件放入 lib/core/ui/pixel/，业务组合留在对应 feature。
  8. 稳定的页面级 API 从 pixel_ui.dart 导出，底层 Painter 不公开。
  9. 补充渲染、回调、语义、键盘和关键尺寸测试。
  10. 新增全局语义或组件类别时同步更新设计文档。
11

测试与验收

  • 没有 Material 默认圆角卡片、按钮、Switch 或 Bottom Sheet 外观。
  • 切角均为水平/垂直像素阶梯，无斜线和抗锯齿灰边。
  • 描边结构清晰，没有重复边框或两套平行轮廓。
  • 按压、悬停、焦点、选中和禁用状态可区分。
  • 交互区域至少 48 × 48dp，键盘焦点顺序合理。
  • 选中、开关和危险状态不只依赖颜色。
  • 横竖屏、小窗口和 2x 文字缩放下无溢出或不可达内容。
  • 减少动态效果开启后状态立即更新且无非必要动画。
  • 页面没有复制 Token、Path、Painter 或交互状态机。
  • 组件测试与 Golden 回归已通过并人工检查差异。
